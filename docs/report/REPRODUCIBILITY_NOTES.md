# 评价口径与复现材料说明

本文档配合[正式报告](report.pdf)与[中文对应稿](report_zh.md)，补充口径和既有材料索引，历史指标保持原记录，新增NMS后处理实测单独列示。

资料状态更新于2026年11月16日；本页记录提交报告之外的复现与最新GUI证据。

## 原生与共同部署评价

| 项目 | 原生验证 | 共同FP32及H10评价 |
|---|---|---|
| 权重 | 各训练器最佳内部AP50:95检查点 | 同一冻结权重导出，H10再作训练集统计校准 |
| 输入及后处理 | 保留对应模型族验证器设置 | RGB转三通道、保持比例、Pillow双线性缩放及114填充到640×640；FP32输入除以255；H10使用UINT8输入 |
| P／R／F1工作点 | YOLO26原生评价器在1000点置信度曲线上取平滑平均F1的最大点；表内F1由所记P／R计算。其他模型保留各自原生记录，本轮未重新恢复其完整选点曲线 | 先按conf≥0.25筛预测，再以IoU≥0.5作一对一匹配；漏检为FN／486 |
| AP | 原生验证器记录 | conf下限0.001；IoU 0.50至0.95，每步0.05；101点精度包络梯形积分 |
| 输出分支 | 对应原生检测头 | YOLO26保留一对一输出；v8/v5式头解码后NMS IoU0.7、maxdet300；RT保留其查询输出 |
| 评分对象 | 同500张内部验证图，也用于选检查点 | 相同500图、486个UAV框，由保存预测及原GT重算 |

PinP2-YOLO的原生AP50:95为31.274%，共同FP32为25.186%，H10为24.351%。前两者相差6.088个百分点，当前记录尚不能分离预处理、候选生成和评分口径的贡献。只有共同FP32至H10的0.835个百分点可描述为本次硬件转换路径的精度变化。八图输出检查不能解释全500图的AP差值，不把这一差值全部归因于量化或模型结构。

已有ONNX检查使用opset17及ONNX Runtime 1.20.1 CPU。YOLO26一对一原始分支容差为绝对1e-3、相对1e-4；conf0.25检测集合要求匹配。下表原始误差取八图及输出张量的最大绝对值，坐标和分数单位不同，仅用于核对既有回执。

| 冻结模型记录 | 检查图数 | 原始分支最大绝对误差 | conf0.25集合一致 |
|---|---:|---:|---:|
| scratch__yolo26n_scratch | 8 | 7.4386597e-05 | 8/8 |
| scratch100__pconv_p2 | 8 | 9.4413757e-05 | 8/8 |
| scratch__rtdetr_l | 8 | 6.9439411e-06 | 8/8 |

RT检查先对300个唯一查询作一对一位置对齐，再应用同一容差。YOLO26低分TopK排序可能不同，未对齐的最终张量逐元素比较会失败；原始一对一分支和阈值集合检查分别保留。检查图索引为固定清单中的0、1、2、3、149、249、349、499。该检查与全500图共同部署评分是不同证据。

## 推断边界

摘要与结论的3.322个百分点是seed42及所记录训练条件下的内部验证差值。B0／B1物理batch32，B2／B3为8，单种子不足以识别稳定结构效应。25%／50%训练比例已各完成100轮及GPU500核验；匹配batch的重复种子和独立采集测试仍未完成。

2026年11月7日新增两组比例权重，仅GPU已测；三档完整记录见[训练比例结果](../results/TRAINING_FRACTIONS_20261107.md)。

## 2026-11-15：NMS与VLM补充

[后处理审计与负面结果](../results/NMS_VLM_AUDIT_20261115.md)给出完整扫描及证据边界。YOLO26原e2e路径无NMS，元数据IoU0.7并未启用。离线NMS阶段重放既有预测，在原坐标裁剪后应用，固定分数及300上限，规范图序下复算。独立标量实现7000例一致；默认0.4下H10 AP31.740%、FP62、TP323／FN163。原跨模型表保留原无NMS精度和22.72 FPS，新变体速度以本轮24次真实运行单独列示，不与旧跨模型数据合并排名。

FP32同样存在重复／匹配冲突，不把现象归因于量化。NMS重放不能彻底解释原生与共同部署AP差值，也不能把32.074%的FP32 NMS0.4 AP当作原生31.274%的复现。

VLM E0–E4已完成并保留为当前策略无优势的负面结果；当前暂停扩大实验。E3同召回下FP12，纯阈值FP11。689次输出无UNCERTAIN；清晰语义正例、数值对照未完成，不推断VLM普遍不适合红外。原始响应、环境、裁剪及SHA证据在私有归档保留。

本轮不训练、不做Mac模型推理、不启动GPU。Pi5／H10通过已有连接恢复访问后完成全部24次实际运行；原始预测逐图一致、指标独立复算及文件哈希核验通过。

最终默认采用NMS IoU0.4（conf0.25、max300）：H10 TP323／FP62／FN163、AP50:95 31.740%。三轮阈值基准为22.89±0.01 FPS、43.70±0.02毫秒／图，NMS26.3±0.1微秒／图；新无NMS对照22.86±0.02 FPS。选择0.4是因为它是召回不变且达到最低FP的测试阈值中较大的一档；0.3仅多0.0026个百分点AP，0.5多1个FP，不用微小速度差异作为选点依据。

新的PinP2/H10部署入口实际在原图坐标还原及裁剪后调用NMS，绑定权重与HEF身份。500图默认策略验收未传入阈值覆盖，实际调用500次，442→385个候选（抑制57框），低分AP候选6969→4368；框、分数、顺序与冻结重放逐一相同，指标独立复算通过。20261115-nms04已发布为该PinP2部署的current版本。验收单次22.56 FPS／44.33毫秒，单列且不并入阈值基准三次重复；未安装摄像头常驻服务。

所选阈值与模型复用同500图验证集，属于内部工程选择；只有1张双UAV图且真值不重叠，密集目标行为未验证。163个漏检和20个鸟类关联FP没有改善。3次硬件重复不构成新增精度样本；当前少量候选的NMS成本不代表密集场景、独立视频或长期摄像头性能。

[部署代码与用法](../../scripts/deployment/README.md)及[验收汇总](../results/NMS_DEPLOYMENT_ACCEPTANCE_20261115.json)记录实际执行证据。

## 图4的软件与来源

[绘图脚本](../../scripts/plot_nms_same_image.py)读取原始验证图、原生标注及冻结H10预测；选择验证图2859，说明唯一在IoU0.4／0.5之间保留框数量发生变化的实例，不把该样例当作平均性能证据。图像SHA已与冻结清单核验。全部conf≥0.25预测均在所示裁剪内，原坐标和分数保持原样。

原图白框对应统一48×32像素裁剪，使用最近邻显示，不调整亮度、对比度或长宽比。无NMS／0.3／0.4／0.5／0.7各保留2／1／1／2／2框；两原框IoU=0.467773。青虚线为UAV真值，橙／红实线分别绑定原始分数0.595030／0.331665。所有框都由现有NMS代码生成，无绘制的假预测。
