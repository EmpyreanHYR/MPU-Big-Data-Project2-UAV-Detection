\begin{abstract}
This report presents a YOLO26n baseline for single-class infrared UAV bounding-box detection on SIRST-UAVB. An audit of the released images found exact-pixel overlap across the original training and validation split and conflicting annotations for some identical images. We fixed a background-view holdout containing 1,438 training and 505 validation images after duplicate removal and annotation quarantine. Training completed 92 full epochs and part of epoch 93 within a fixed execution window. Final validation of the selected checkpoint achieved 66.5\% precision, 49.2\% recall, 56.2\% mAP@0.5, and 23.2\% mAP@0.5:0.95 on 491 UAV instances. These measurements establish the baseline for subsequent shallow pinwheel-shaped convolution and high-resolution P2 experiments.
\end{abstract}

\section{Background and Study Design}
Small infrared UAVs contain few pixels and limited texture. Bright background structures and birds can resemble the target, while small coordinate errors strongly affect box overlap. We study bounding-box detection using YOLO26n as the lightweight baseline\cite{jocher2026yolo26,ultralytics2026docs}. Pinwheel-shaped convolution (PConv) provides directional shallow sampling for infrared small-target features\cite{yang2025pconv}; a stride-4 P2 prediction branch provides a second way to preserve spatial detail.

The implementation contains B0 (baseline), B1 (a layer-1 PConv replacement), and B2 (an added P2 branch). The experiment reported here trains B0. B1 and B2 currently have model-construction and checkpoint-restoration checks; their detection improvements remain to be measured using the same fixed data protocol.

\section{Dataset Audit and Preparation}
SIRST-UAVB is the main dataset\cite{yang2025pconv}. The acquired archive contains 3,000 grayscale images at 640 by 512 pixels. Direct inspection of its native labels counted 2,961 class-0 and 1,747 class-1 boxes. We identified class 0 as UAV and class 1 as bird by cross-checking boxes against masks and the authors' description that bird targets are excluded from masks. Positive mask pixels overlapped 2,955 of the class-0 boxes and only one class-1 box, with two pixels in that exceptional overlap. Native boxes were retained rather than regenerated from masks.

The original 2,400/600 split has 496 exact-pixel groups shared across training and validation. Three additional pixel-identical groups have inconsistent labels. We isolated those conflicts, the six UAV images without corresponding positive mask pixels and their pixel-identical copies, and close background views at the split boundary. Exact-pixel deduplication and the fixed background-view review produced the counts in Table~\ref{tab:data}. Bird boxes are retained in the audit manifest but omitted from the single-class UAV training labels.

The release provides no original video or session identifiers. The grouping therefore represents inferred background-view families, with nearby facade views held out for validation. \section{Model and Experimental Settings}
B0 uses the n-scale, single-class YOLO26 architecture with prediction strides 8, 16, and 32 and its end-to-end output branch. The constructed training model has 2,504,190 parameters. For consistent initialization across future variants, we transfer only same-name, same-shape tensors in layers 0--16 from the official YOLO26n checkpoint: 348 tensors were copied. Layers from 17 onward are randomly initialized. Thus the experiment uses a shared-prefix transfer policy rather than full-model pretrained initialization.

Training ran on one RTX 2080 Ti with Python 3.10.8, PyTorch 2.1.2+cu118, and Ultralytics 8.4.184. Table~\ref{tab:settings} records the effective settings. The automatic optimizer resolved to AdamW at an initial learning rate of 0.002; this effective value supersedes the generic default in the argument file. Standard training augmentation includes mosaic, scaling, translation, and horizontal flipping. Validation uses the fixed 505-image split without training augmentation.

The selected checkpoint was saved at epoch 81, as confirmed by its stored epoch index and the validation CSV.

\subsection{Timing and Artifact Verification}
The final GPU validation reported 0.1 ms preprocessing, 3.1 ms inference, and 0.1 ms postprocessing per image, using validation batches of eight. These are framework timings for offline images. Camera input, video decoding, display, and device transfer require a separate end-to-end benchmark on the deployment device.

The cloud log confirms that both best.pt and last.pt were written and optimizer-stripped to approximately 5.4 MB before final validation returned. The independently hashed local archive was captured just before shutdown: it contains the selected epoch-81 best checkpoint (25,780,216 bytes, including training state) and an epoch-92 last checkpoint (25,781,880 bytes). Both deserialize successfully and each has 708 state tensors with finite floating-point values. Both final stripped files have now been retrieved: each is 5,388,158 bytes, and each local SHA256 matches both the pre-shutdown artifact manifest and a fresh cloud SHA256. Both deserialize with finite floating-point state tensors. Every final-best tensor equals the archived epoch-81 EMA tensor; final-last differs from the epoch-92 snapshot. Optimizer stripping resets the stored epoch to $-1$, so training progress is identified from the final 93-row CSV, stopping record, and console log. The last CSV row follows the partial epoch; Fig.~\ref{fig:curve} retains only the 92 complete epochs. The retrieval session used no GPU and was stopped after transfer.

\section{Edge Deployment and Further Experiments}
The next algorithm experiments replace the second backbone convolution with PConv and add a separate stride-4 P2 branch. Their relative recall, AP, and inference cost will be compared with B0 under a matched protocol. Bird-box matching and target-size groups will provide more specific error analysis.

YOLO26n conversion for H10, Raspberry Pi execution, and real infrared-video timing have not yet been measured for this trained baseline. The deployment stage will record the compiler/runtime combination, conversion success, any accuracy change, and end-to-end video latency. The GPU validation timing above is the current measured reference.

\section{Conclusion}
We completed a real-data YOLO26n baseline with a fixed, audited background-view holdout. The selected epoch-81 checkpoint achieved 56.2\% mAP@0.5 and 23.2\% mAP@0.5:0.95 after 92 full training epochs and part of epoch 93. Local checkpoint integrity and the final cloud save messages were checked, and the cloud platform was confirmed stopped after the run. The remaining study compares shallow directional sampling and higher-resolution prediction using this baseline and then measures deployment performance.
