# GUI 与 H10 真机联调（2026-11-16）

本记录验证 PyQt 界面到真实 Raspberry Pi 5 / HAILO10H 的图片、视频检测链路，使用 PinP2-YOLO scratch100 模型，confidence0.25、NMS IoU0.4、max300。

## 验证口径

Mac 使用 PyQt6，服务端使用 HailoRT5.1.1；Pi 本机使用 PyQt5 5.15.11 / Qt5.15.15，验证实际窗口、绘制、工作线程和导出。自动化 GUI 验证在离屏 Qt 平台执行，截图由真实窗口生成。

图片取自现有 SIRST 验证素材，64张覆盖含目标及空预测情况，逐框、逐分数核对既有部署验收输出。视频由 UAV-CB 的真实红外图像按发布文件名排序合成，FFV1 无损编码；因画面时间不连续，编码25FPS只是播放速率。

## 已观察到的结果

| 场景 | 输入 | 结果 |
|---|---:|---|
| Mac → H10 单图 | 1张 | 检测框和分数与验收记录逐值一致，截图导出正常 |
| Mac → H10 图片目录 | 64张 | 64/64逐值一致，共47个检测框 |
| Mac → H10 无损视频 | 30帧 | 全部完成；导出视频30帧可解码 |
| Pi 本机 GUI → H10 无损视频 | 30帧 | 30/30与Mac无损结果逐值一致；实际更新30次，视频导出30帧 |
| Mac → H10 JPEG95视频复测 | 300帧 | 300/300完成，共204个框；12秒暂停恢复通过，导出视频300帧可解码 |
| Mac 原生桌面窗口 | 9帧后主动停止 | 开始、暂停、恢复、停止、实验表、退出通过；导出视频9帧，进程正常退出 |
| 设备占用保护 | 第二次启动 | 共享锁拒绝新服务，原服务继续运行 |

Pi 本机30帧（含读视频、无损PNG编码、本机HTTP、H10、Qt更新和写出）耗时4.909秒，约6.11帧/秒；服务处理均值42.17ms，请求均值52.64ms。

Mac 经 Tailscale 中继：64张图片请求均值1459.36ms，30帧无损视频3303.44ms，两者的H10处理均值约46ms。300帧JPEG95运行耗时671.42秒（含12秒主动暂停），请求均值2185.99ms、P95 3962.79ms，H10处理均值45.80ms。瓶颈在中继网络，而不在H10。

## 联调修复

- 用HTTP/1.1长连接减少逐帧重新建立连接；最多4个连接，H10调用用互斥锁串行保护，忙时返回409。
- PNG/JPEG图片直接上传原文件，不先解码再重新编码，保持原始像素并减少上传量。
- 切换素材或输入类型时清空旧标注路径；视频／摄像头自动选择实时引擎，避免误用图片标注。
- 用真实窗口更新时间计算 `Display FPS`，同时保留H10处理耗时和请求耗时。
- 视频可选JPEG95，但默认保留无损PNG。同一段前30帧PNG输出18个框，JPEG95输出17个框，两者不等价；视频没有标注，无法判断哪个更准确。
- 长视频第一次运行在207帧后出现 `Remote end closed connection without response`。修复方式是加长网络等待窗口、增加脱敏错误日志，客户端按完整请求时间重建连接，且不自动重发可能已执行的推理。
- 修复混合尺寸图片导出视频失败时，摘要与已处理帧计数不一致的问题。
- 一键启动器通过SSH标准输入传入随机令牌，GUI退出时只结束本次启动的服务和自有隧道。
- Mac原生辅助功能扫描动态Qt表格时出现SIGSEGV，Qt6.12.0和6.7.3均复现。改为富文本表格后，Qt6.12.0原生窗口复测通过；问题与 [Qt上游表格辅助功能问题](https://qt-project.atlassian.net/browse/QTBUG-149612) 属同一子系统。
- 停止请求到达时可能已导出最后一帧但尚未显示；结束后的处理计数改为取最终保存摘要，避免顶部数量与完成状态不一致。
- 界面改为英文主文案、中文辅助；支持Pi现有PyQt5，未改系统Qt或训练环境。

## 测试状态

长视频修复后300帧复测通过，原生窗口正常退出（退出码0），H10设备与共享锁均已释放。Mac 29项GUI测试全部通过；Pi 29项中28项通过、1项Mac专属测试跳过，完整统计见 [配套JSON](GUI_H10_20261116.json)。摄像头入口目前只做了程序入口，没有接真实摄像头验收。
