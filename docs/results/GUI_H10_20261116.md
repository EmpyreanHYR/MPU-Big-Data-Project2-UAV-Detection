# GUI 与 H10 真机联调（2026-11-16）

本记录验证 PyQt 界面到真实 Raspberry Pi 5 / HAILO10H 的图片、视频检测链路。使用冻结 PinP2-YOLO scratch100 模型，confidence0.25、NMS IoU0.4、max300；不训练、不导出新模型、不启动云端实例。

## 验证口径

Mac 使用 PyQt6，服务端使用 HailoRT5.1.1。Pi 本机另使用已有 PyQt5 5.15.11 / Qt5.15.15，验证实际窗口、绘制、工作线程和导出。自动化 GUI 验证在离屏 Qt 平台执行，截图由真实窗口生成；离屏吞吐率不是物理显示器刷新率。

图片取自现有 SIRST 验证素材，64张覆盖含目标及空预测情况，逐框、逐分数核对既有部署验收输出。视频由 UAV-CB 的真实红外图像按发布文件名排序构建，FFV1 无损编码，每帧解码像素已核验；**它不是核实过时间连续性的原始摄像头录像**，编码25FPS不是实测拍摄帧率。本次测试证明软件链路可处理视频，不新增独立视频准确率结论。

## 已观察到的结果

| 场景 | 输入 | 结果 |
|---|---:|---|
| Mac → H10 单图 | 1张 | 检测框和分数与验收记录逐值一致，截图导出正常 |
| Mac → H10 图片目录 | 64张 | 64/64逐值一致，共47个检测框 |
| Mac → H10 无损视频 | 30帧 | 全部完成；导出视频30帧可解码 |
| Pi 本机 GUI → H10 无损视频 | 30帧 | 30/30与Mac无损结果逐值一致；实际更新30次，视频导出30帧 |
| Mac → H10 JPEG95视频复测 | 300帧 | 300/300完成，共204个框；12秒暂停恢复通过，导出视频300帧可解码 |
| Mac 原生桌面窗口 | 9帧后主动停止 | 开始、暂停、恢复、停止、实验表、退出通过；导出视频9帧，进程正常退出 |
| 设备占用保护 | 第二次启动 | 共享锁拒绝新服务，原服务继续运行 |

Pi 本机30帧包含视频读取、无损PNG编码、本机HTTP、H10、Qt更新和视频写出，耗时4.909秒，约6.11帧/秒；服务处理均值42.17ms，请求均值52.64ms。这是一次短功能运行，包含截图开销，不是正式硬件基准。

Mac 通过当前 Tailscale 中继连接：64张图片请求均值1459.36ms；30帧无损视频请求均值3303.44ms；两者H10处理均值约46ms。修复后的300帧JPEG95运行耗时671.42秒（含主动暂停12秒），请求均值2185.99ms、P95为3962.79ms，H10服务处理均值45.80ms。网络和客户端耗时与H10耗时分开记录，不能把播放上限当实际帧率。

## 联调修复

- 用HTTP/1.1长连接减少逐帧重新建立连接；最多4个连接，H10调用用互斥锁串行保护，忙时返回409。
- PNG/JPEG图片直接上传原文件，不先解码再重新编码，保持原始像素并减少上传量。
- 切换素材或输入类型时清空旧标注路径；视频／摄像头自动选择实时引擎，避免误用图片标注。
- 用真实窗口更新时间计算 `Display FPS`，同时保留H10处理耗时和请求耗时。
- 视频可选JPEG95，但默认保留无损PNG。同一段前30帧PNG有18个框，JPEG95有17个框，输出不等价；没有视频标注，不能据此判定哪一个更准确。
- 长视频第一次运行在207帧后出现 `Remote end closed connection without response`。失败状态及部分输出保留。服务保持运行；增加网络等待窗口与脱敏错误日志，客户端按完整请求时间保守重建连接。不会自动重发可能已执行的推理。
- 修复混合尺寸图片导出视频失败时，摘要与已处理帧计数不一致的问题。
- 新增受限的一键启动器：随机令牌通过SSH标准输入传入，GUI退出时仅核验并结束本次PID/启动时间/命令匹配的服务及自有隧道。
- Mac原生辅助功能扫描动态Qt表格时出现SIGSEGV；Qt6.12.0和6.7.3均观察到失败。改为富文本表格，保留表头排序、文本复制与目标选择；Qt6.12.0原生窗口复测通过。未关闭系统辅助功能。调用栈与 [Qt上游表格辅助功能问题](https://qt-project.atlassian.net/browse/QTBUG-149612) 涉及同一子系统，未将该关联当作精确根因证明。
- 停止请求到达时可能已导出最后一帧但尚未显示；结束后的处理计数改为取最终保存摘要，避免顶部数量与完成状态不一致。
- 界面改为英文主文案、中文辅助；支持Pi现有PyQt5，未改系统Qt或训练环境。
