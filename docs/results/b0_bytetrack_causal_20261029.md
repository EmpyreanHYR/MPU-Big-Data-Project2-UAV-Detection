# B0＋因果时序关联：开发序列多检出13帧，误报未增加

2026-10-29，按“同一输入上精确率不低于原B0、召回率提高”的目标，对已保存并完整核验的B0检测框进行了单配置时序对照。**在此前已观察的300连续帧红外开发序列上，正确检出60→73，误报保持5，精确率92.31%→93.59%，召回率20.00%→24.33%。** 这是该序列上的初步证据，不是独立测试或跨场景改善结论，部署仍保持原B0。

| 方法 | TP / FP / FN | 精确率P | 召回率R |
|---|---:|---:|---:|
| 原B0，conf≥0.25 | 60 / 5 / 240 | 92.31% | 20.00% |
| 保留B0输出＋已建立轨迹关联的当前帧低分框 | 73 / 5 / 227 | 93.59% | 24.33% |

新增13个当前帧框均匹配目标，新增检出13帧、丢失0帧；没有用轨迹预测框填补无检测帧。源预测来自此前全SHA及逐帧核验的同路径FP32、TF32关闭、one-to-one、640方形输入参考。本次只读取保存框进行后处理，没有重新执行模型或训练。[机器可读结果](b0_bytetrack_causal_20261029.json)保留协议及预测哈希。

采用[ByteTrack](https://github.com/FoundationVision/ByteTrack)思路，实际实现为固定Ultralytics 8.4.184的ByteTrack/XYAH Kalman定义，配NumPy输入适配与LAPJV限成本匹配。只提取所需定义，不导入模型包。配置在新关联执行及计分前冻结：high=0.25、low=0.10、new_track=0.25、buffer=30帧、match=0.8、fuse_score=True；没有在IR300上搜索配置或按结果调参。30帧缓冲不代表已知视频帧率。

每帧完整保留原B0的所有≥0.25框；只有已建立、激活且本帧确有检测观测的轨迹，才可补入0.10<conf<0.25的框。新增框沿用该帧原始检测坐标，不输出Kalman平滑框或丢失后的外推框；与原高分框或先接受的新增框IoU≥0.5时不再补入。关联只读过去与当前帧，不读取GT或未来帧。它不能凭低分框自行初始化目标，也不能找回完全没有候选的目标。

七组边界检查覆盖空输入、低分不能起轨、已建立轨迹补低分、无观测不输出外推框、完整检测索引、原高分框保留及退化框拒绝。另用标准库核验全部300行与已确认归档相同、GT与冻结媒体标注一致，并用此前冻结的计分实现逐帧复算；原B0的60/5/240也准确复现。同一主代理进行源码与另一计分方法核验，没有第二审查者。不能把仅后处理耗时当成模型、设备或完整视频速度。

局限仍明显：序列已经用于开发，全部帧有目标，无法据此估计独立背景误报/小时；对新的相机运动、长时间遮挡和伪轨迹仍需验证，跨录制族增益也未获支持。也未修改或提升原505散图的单帧结果。下一对照已冻结为两个此前观察的保留录制族各取第1–300连续帧，包含所有exist状态，使用同一配置；[连续600帧后续对照](b0_bytetrack_contiguous_20261029.md)现已完成并完整核验：TP保持2、FP22→31，未达到预定目标；两次输入不同，不能将本序列的13帧增益当作跨族收益。后续结果仍为已观察录制族的开发评价。
