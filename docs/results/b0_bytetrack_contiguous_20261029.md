2026-10-29，对两个此前已观察的录制族各取第1–300帧，完成固定配置的因果时序对照。**原B0正确检出2帧，关联后仍为2帧；误报22→31，精确率8.33%→6.06%，召回率保持0.33%。** 两个族及合计均未达到“精确率不下降且召回率提高”的预定要求，不采用该配置替换部署。[机器可读结果](b0_bytetrack_contiguous_20261029.json)记录计数、协议及预测哈希。

新增9个当前帧低分框均为IoU≥0.5计分下的FP，与该帧已标UAV框的IoU均为0；没有新增或丢失正确检出帧。具体误检物体类别未确认。这说明该配置可能接纳额外误检，无法仅凭先前单序列上的增益推断跨录制族有效。先前[IR300开发对照](b0_bytetrack_causal_20261029.md)的13帧增益保留为历史结果，不因本次负结果修改。

两个窗口来自[作者Anti-UAV600 train分发](https://github.com/ZhaoJ9014/Anti-UAV/blob/master/README.md)中早于扩充训练保留的录制族，此前已用于开发评价；从完整连续窗口取帧，不把原等距200帧或505散图串成视频。选帧在新预测前冻结，不按预测或GT另换窗口。实际600帧均有标注目标，不能用于估计独立背景误报/小时；录制族名称和低成本重复筛查也不证明真实视频来源独立。它们不进入训练或校准。

本次使用原B0的既有原始ONNX，在ARM CPU、ONNX Runtime 1.23.2、FP32、单线程、640方形输入、batch=1运行；这是提前记录的运行时替代协议，与此前Windows PyTorch运行区别披露。模型、输入原字节、600张Pillow/OpenCV像素及原GT均核验。43张与已核验Windows参考重叠的图像，在score>0.10和score≥0.25处框数、类别及顺序一致，最大坐标误差0.0000611像素、分数误差0.000000507；这是43帧子集一致性，不能声称完整600帧的跨运行时等价。没有训练、校准或新权重选择，也不将本次低优先级CPU运行计时当作完整视频或加速器性能。

关联复用[此前固定的ByteTrack适配器](b0_bytetrack_causal_20261029.md)，high=0.25、low=0.10、new_track=0.25、buffer=30帧、match=0.8、fuse_score=True；每族独立重置，不搜索参数。保留全部B0高分框，只补入已建立激活轨迹的本帧真实低分观测，沿用原框，不输出外推框、不读GT或未来帧、不以低分起轨。先冻结关联协议并保存预测，再计分。

输入603个文件逐SHA核验，结果归档23个文件及清单全部SHA、CRC、路径、大小核验，并逐帧复算600行GT、源SHA和计分；运行端已确认准确归档SHA及进程退出。另用单目标的独立标量IoU计分方法复算所有600行与9个新增框，结果一致。同一主代理完成源码和另一方法核验，没有第二审查者。

原505单帧指标保持，未证明达到其P≥75.17%、R>46.23%的严格目标，部署仍为原B0。本次结果不支持把该时序关联作为通用召回修复。SSTNet仍须取得并核验完整任务权重，之后按冻结连续输入和明确运行时评价；目前没有SSTNet本项目指标，不采用部分或随机权重代替。
