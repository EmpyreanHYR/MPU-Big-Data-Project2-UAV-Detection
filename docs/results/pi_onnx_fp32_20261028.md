# Pi CPU的ONNX FP32配对基准

2026-10-28，使用实际Pi CPU和CPUExecutionProvider完成B0原始one-to-one ONNX基准。与[导出一致性检查](onnx_fp32_parity_20261028.md)使用相同模型、原始300个JPEG、640方形114letterbox、confidence0.25、maxdet300、匹配IoU0.5，没有额外NMS。未使用H10、训练或校准。[逐次机器可读结果](pi_onnx_fp32_20261028.json)。

预热20帧，75/150/300为同一序列的嵌套前缀，各重复三次。每次预测均逐帧对照此前冻结的完整B0 FP32参考：数量、类别一致，坐标和置信度均通过预设门槛；最大坐标差3.05176e-5像素、置信度差1.40071e-6。三次300帧结果均为TP60/FP5/FN240，P/R/F1保持92.31%/20.00%/32.88%。低召回率和序列独立性限制未改变。

路径计时包括JPEG读取/解码、预处理、ORT模型调用、one-to-one主机解码和原图坐标还原；计分与JSON写出不计入该路径计时，另有包含这些步骤的wall时间记录。模型会话初始化0.05177秒、预热不计入上述速度。它不是视频容器解码/显示/编码的端到端速度，更不是H10成绩或加速比。

实际aarch64/Python3.13.5、ORT1.23.2、NumPy2.2.4、OpenCV4.12.0，四个intra-op线程、一个inter-op线程。测试期间一次设备读数约64.8°C、2.4GHz、节流标志0；未锁频或全面控制温度、后台负载，因此不声称最大硬件性能。ORT的GPU发现警告未改变CPUExecutionProvider断言，模型没有调用NPU。

输入包及每成员SHA先核验，结束归档与全部成员SHA取回通过，序列化300行另行计数和对照。核验由同一主代理完成，不称外部审查。Pi/Windows继续运行，未关闭设备。H10的新HEF仍未编译，当前WSL启动资源错误待解决，见[部署准备](../deployment/READINESS_20261028.md)。
