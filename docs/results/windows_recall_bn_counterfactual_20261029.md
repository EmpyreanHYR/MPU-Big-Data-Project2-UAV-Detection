# BN运行统计反事实：影响原场景表现，直接换回仍不足

2026-10-29，在[低学习率对照完整预测包核验完成](windows_recall_lr_control_20261029.md)后，固定协议进行了两次无梯度推理。只交换原B0与低学习率best的BN运行统计，其他参数逐项保持各自来源，考察原505验证性能下降是否与这些统计有关。**更换BN统计会明显改变检出与误检，但直接换回原统计仍不能满足精确率约束，部署继续保留原B0。**

模型推理及完整成果核验均已完成：1205393字节归档的11个文件及清单全部通过SHA、CRC、安全路径和大小检查；两组505行GT、顺序和四个阈值的计分逐行复算一致，原参考预测与计分准确复用。运行端已确认准确归档SHA及本次进程退出。[机器可读记录](windows_recall_bn_counterfactual_20261029.json)记录完整核验状态。

这是2×2对照：学习参数取原B0或低学习率best，BN统计取原B0或低学习率best。两个原样模型的预测复用此前已全SHA/逐帧核验的同路径参考，只新执行两个混合态，未重新训练、校准或保存混合权重。未使用IR300或两族200帧。

均为固定505、conf=0.25、匹配IoU=0.5、544×672矩形输入、batch8、FP32、关闭TF32、one-to-one且无额外NMS。新推理复用同一数据集构造与官方端到端置信度过滤，逐图输入顺序、源图SHA和GT几何与参考检查一致。本次只计算固定阈值计数，没有计算官方AP或验证损失，不能与此前官方P/R工作点混用。

保留微调参数、换回原BN统计时，TP从192升至230，但FP也从85升至156，精确率降为59.59%，低于预设73.1656%约束。保留原参数、换上微调BN统计时，TP从227降至144。两次干预说明BN统计不是与表现无关的部分；同时，直接交换未形成兼顾召回和误检的修复，不能说BN是唯一根因，或据此断言冻结BN训练一定更好。

实际有114个BatchNorm2d模块；两来源的114组running_mean和114组running_var均不同，num_batches_tracked均相同。只交换这三类缓冲区，BN的仿射参数和其他所有状态逐张量精确保持来源；推理前后所有状态哈希相同，全部模块处于eval且无参数梯度。两份源检查点原有浮点存储均为FP16，推理时升至FP32，未声称恢复保存前精度。两混合态可能破坏参数与统计的共同适配，故这里只是有限范围的机制证据。
