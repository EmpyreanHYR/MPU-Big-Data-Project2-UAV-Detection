# 保存预测的附加NMS试验（2026-10-29）

[误检归因](windows_recall_fp_attribution_20261029.md)发现原one-to-one输出有重复检出，因此对已经全SHA核验的640尺寸预测做独立后处理试验。没有重新运行模型、更新参数或训练；附加NMS会改变原本无需额外NMS的推理方式，不能仍将此候选称作纯端到端免NMS部署。

运行前固定：原B0与微调best的one-to-one预测，四个原有置信度0.25/0.10/0.05/0.01，附加NMS IoU为0.3/0.5/0.7及不附加，共32组。只按505验证图，在P≥原B0/one-to-one/640/0.25减0.02的约束下最大化R；写出选择记录后，才评价该设置的IR开发序列。没有利用IR选择阈值。

该范围内选出“微调best、置信度0.25、附加NMS IoU0.5”：

| 设置 | 验证TP / FP | 验证P / R | IR TP / FP | IR P / R |
|---|---:|---:|---:|---:|
| 原B0 one-to-one，无附加NMS | 227 / 75 | 75.17% / 46.23% | 60 / 5 | 92.31% / 20.00% |
| 微调best one-to-one，无附加NMS | 243 / 126 | 65.85% / 49.49% | 105 / 78 | 57.38% / 35.00% |
| 微调best one-to-one，附加NMS0.5 | 242 / 80 | 75.16% / 49.29% | 103 / 71 | 59.20% / 34.33% |

在验证集上，附加NMS明显减少微调模型的重复框，恢复精确率，保留了大部分召回。但IR误检仍为71，远高于原部署5，不能宣称跨场景优化完成或直接采用新默认。此前原B0/one-to-many/640/0.25在验证集P/R为82.48%/52.75%，也高于此处候选；本次选择仅限one-to-one后处理候选，不是全部分支的全局最优。

四项纯NMS边界检查通过；另写一种NMS实现和匹配计数复算，所选设置验证242TP/80FP/249FN、IR103TP/71FP/197FN及逐帧输出一致。同一主代理完成核查，无第二审查者。记录计算耗时不属于模型、Pi或H10基准。

IR300已参与开发且帧相关，不是独立测试；IR未用于训练、校准或选择阈值，没有独立测试或新权重收益证据。原历史结果、四阈值比较、权重与部署默认保持。[机器可读结果](windows_recall_postnms_20261029.json)。
